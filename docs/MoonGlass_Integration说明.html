MoonGlass_Integration 说明

面向芯片工程师的可读说明 · 中文 · 自包含单页

这是什么：一套让任意 coding agent（Workbuddy / Claude Code / DeepSeek harness / Cursor 等）靠 YAML 契约做 SoC 组装与连线的规则 / Schema / 约束包。自然语言是意图，YAML 是真源；校验器只做规则执行。它不是集成引擎，也不是 MoonGlass 产品内的接线功能——协议与结构清楚之后，Agent 可现场写 glue；本包刻意不做永久集成工具产品。

1. 定位与边界

是不是
IP / Subsystem / SoC 的 JSON Schema + 命名与连线约定 FuseSoC / IP-XACT / Vivado IPI 的替代品（刻意不做）
Agent 可读的 AGENTS.md / CLAUDE.md / .cursorrules MoonGlass 里跑集成的功能模块
示例 YAML + 薄校验脚本 tools/validate.py 永久的「集成工具产品」或重型 elaborator

与 MoonGlass 的关系

MoonGlass 适合托住这类规则、描述与状态（托管 / 检查契约）。本包不在 MoonGlass 内执行 SoC 接线。社区可先挂这套组建拉讨论与流量，与核心产品解耦。任意 coding agent 都可按本规则包执行集成。

边界一句话 本仓库交付的是「契约 + 规则 + 薄校验」；RTL 展开与 glue 由 Agent 按 YAML 现场完成，不在本包产品化。

2. 整体架构

契约分三层 YAML，由下到上组装；每一层有对应 JSON Schema。

Layer 1

IP 接口

kind: ip — 时钟 / 复位 / 端口 / 参数 / 可选 memory_map。
Schema: ip_interface.schema.json

Layer 2

Subsystem

kind: subsystem — 实例化 IP、内部 links、exports、相对 address_map。
Schema: subsystem.schema.json

Layer 3

SoC Top

kind: soc — 实例、connections、clock/reset tree、绝对 address_map、pads。
Schema: soc_top.schema.json

4. 自研契约字段说明

以下均为自研字段名与语义，不是某厂商 schema 的拷贝。完整约束见各层 Schema。

身份与分层

字段出现层说明
kind全部常量：ip | subsystem | soc
name全部蛇形标识，^[a-z][a-z0-9_]*$
version全部契约版本（semver-ish）；无 VLNV 强制要求

端口：role vs bus_role、bundle、时钟域

字段含义取值 / 注意
ports[].name/dir/width 信号名、方向、位宽 dir: in|out|inout；必填
ports[].protocol 逻辑协议标签 如 apb3、axi4lite、irq、uart、raw
ports[].role 协议内信号角色 如 psel / pready / txd。不要把 initiator/target 写在这里
ports[].bus_role 总线端点角色（可选） initiator | target | monitor | passthrough；同一逻辑总线宜同值
ports[].bundle 逻辑接口组 id（可选） 如 apb_s；与 connections.kind: bundle 配合整组连线
ports[].clock_domain 时钟域标签（可选） 常与 clocks[].name / SoC clock_tree 名对齐；非 HDL 端口
ports[].cdc CDC 意图（可选） none | crossing | async_handshake | unknown
记忆口诀 role = 线在协议里叫什么（PSEL…）；bus_role = 这块接口站主端还是从端。二者绝不混用。

连接、时钟复位树、地址、参数

字段层说明
connections[].from/to SoC 端点：instance.port | clock:<n> | reset:<n> | pad:<n> | const:<v>（const 仅作 from）
connections[].kind / links[].kind SoC / Subsys port（默认，单信号）| bundle（整组；sink 侧同 bundle 端口须覆盖完整）
links[] Subsystem 子系统内部实例间连线
clock_tree / reset_tree SoC 顶层时钟/复位源；复位带 polarity（须匹配 sink 契约）
clocks[] / resets[] IP IP 所需时钟与复位（含极性、async）
address_map SoC / Subsys SoC 为绝对 base（int 或 0x…）；子系统为相对 base_offset。无说明的重叠视为错误
memory_maps IP 可选寄存器窗（name/offset/width/access）；不做完整 bitfield 手册
parameters IP + 实例覆盖 IP 声明 type+default；实例 parameters 只能覆盖已声明键
pads[] SoC 片外焊盘；经 pad:<name> 参与 connections
exports Subsystem 向上暴露的 clocks/resets/ports（可带 bundle / bus_role / cdc）

5. 规则与场景

完整条文：rules/integration_rules.md。场景 walkthrough：rules/scenarios.md。

连线合法性摘要

  • 端点必须可解析（实例端口 / clock / reset / pad / const）。
  • 位宽一致（或显式切片并在 YAML 写明）。
  • 两端都声明 protocol 时必须相等。
  • 同 bundle / 同协议组：优先单一 clock_domain；跨域须标 cdc。
  • kind: bundle 时，sink 侧该 bundle 全覆盖，否则错误。
  • 复位极性匹配；必需时钟/复位默认不得悬空。

7. 校验与「完成」定义

tools/validate.py 是规则执行器，不是集成器。它做：JSON Schema 校验；端口属性枚举/一致性；以及跨文件 bundle 闭包、bus_role 配对（策略 A）、0.1.3+ 的 fabric/adapters、0.1.5 的 bit-slice。解析 ref/ip 仅用于检查，不生成 glue HDL。

路径解析顺序：引用文件同目录 → --root / 环境变量 MOONGLASS_INTEGRATION_ROOTS → 本包 examples/（可用 --no-examples-fallback 关闭）。Bundle 端点可用 instance.bundle:<id>。

完成清单（Definition of Done）

  • 相关 YAML 已更新且仍通过 schema
  • python tools/validate.py 退出码 0（或文档化的等价检查）
  • 报告生成/修改的 RTL / wrapper / 脚本路径
  • 未在 YAML 外发明端口；契约变更须显式点出
  • 地址 / 时钟 / 复位 / CDC 意图已反映在 SoC（或子系统）YAML
Agent 禁区 不得为了「能编过」而静默加宽总线或改极性；先改 YAML（必要时经人确认），再 regenerate。

9. 缺口状态（已做 / 有意未做）

0.1.2 已交付 9.1 / 9.2 / 9.3；0.1.3–0.1.5 又补上 PicoSoC 实测缺口：fabric decode/mux、adapters、bit-slice。下列 9.4 / 9.5 仍为有意保留。跨文件/fabric 能力仅用于校验，本包仍不是永久集成器。

9.1 跨文件 bundle 闭包校验 — 已做（0.1.2）

做什么
校验器按约定解析 instance.ref / instance.ip，对 kind: bundle 连接加载子 YAML，核对 sink 侧 bundle 成员是否被 source 覆盖，并检查位宽 / protocol。端点推荐 instance.bundle:<id>（两端本地 bundle 名可不同，如 apb_m↔apb_s）。
路径解析顺序
① 引用 YAML 同目录（含 {ip,subsys,soc}/ 子目录）；② --root / MOONGLASS_INTEGRATION_ROOTS；③ 本包 examples/ 回退。缺失文件、kind 不符、name≠ref、循环引用 → 报错。
示例
examples/soc/demo_soc.yaml：host0.bundle:apb_m → periph0.bundle:apb_s；host IP 为 examples/ip/apb_host_stub.yaml。
边界
只做检查，不生成 glue HDL，不自称 elaborator 产品。

9.2 initiator↔target 配对（策略 A）— 已做（0.1.2）

做什么
在跨文件端点解析之后：若两端都填写了 bus_role 且落在 {initiator,target}，则必须互补（initiator↔target）。任一端省略 → 不报错。同 bundle / 同 protocol 内部一致性检查仍保留。
monitor / passthrough
monitor 可挂任一侧；passthrough 视为桥 — 不因此误报配对失败。仅当两端都是 initiator/target 时强制互补。

9.3 多时钟 CDC 示例 — 已做（0.1.2）

做什么
demo_soc 增加 aon_clk；UART IRQ（periph0.irq_uart，源域 pclk，cdc: crossing）连到 pad:irq_uart_aon，connection note 写明需同步进 aon 域。场景 S7 指向这些文件。
边界
意图标记给 Agent 用，不是签核级 CDC（不自动插同步器网表、不替代约束/签核证据）。

9.3b fabric decode/mux — 已做（0.1.3）

SoC fabric[]：kind: decode_mux + slaves 地址窗 + ready_merge/rdata_merge。校验窗口与 master 端点；不生成 HDL。

9.3c adapters（异构从设备）— 已做（0.1.4）

adapters[]（partial_map/width_remap/bridge）由 fabric.slaves[].adapter 引用；检查 to_port 与宽度。

9.3d bit-slice 端点 — 已做（0.1.5）

instance.port[N] / [M:N]；有效位宽参与连线检查。示例：pad:irq_5→cpu.irq[5]。

9.3e 连连看 NL↔字段 — 已做（0.1.6）

文档/prompt：rules/nl_field_map.md + prompts/scenario_match.md。无新 schema。未来可选（未做）：连接方向检查、fabric↔connections 强制、专用 spimem_cfg adapter 硬化。

9.4 寄存器 bitfield / VLNV / 厂商互换 / GUI — 有意未做

刻意不吸收
完整寄存器 bitfield / RAL 电子手册；强制 VLNV 目录；厂商工具互换格式；GUI / Block Design 画布坐标；专有 TCL / coreKit；把 Scala Diplomacy / LiteX 运行时对象当 YAML 真源。
原因
（1）专利与知识产权风险；（2）与「Agent + YAML 最小真源」冗余或偏离——本包装配关心接口/地址/时钟复位/连线，不关心 BD 布局或厂商目录编号。

9.5 不做永久集成工具产品 — 有意未做

原则
协议与结构清楚之后，AI 可现场定制 glue。本包提供契约与规则；Agent 可写一次性 helper。把「永久集成器」产品化会与此冲突。0.1.2 的跨文件能力仅限校验，不改变这条边界。
与 MoonGlass
MoonGlass 可后续托管/检查这些描述；它不替代 Agent elaborator，本包也不把集成器塞进 MoonGlass。
读缺口时请记住 「缺」≠「漏」。0.1.6-draft：契约可读、单文件 + 跨文件闭包可校验、场景可映射、连连看可匹配必填字段、Agent 有清晰禁区——而不是假装已是全功能 SoC 装配器。
