1. 结论摘要

在 0.1.2 pilot 基础上做了三轮规则包迭代，把原先只能写 note 的三类缺口变成了可校验的自有 YAML： fabric（译码/mux）、adapters（异构从设备）、bit-slice（IRQ 打包）。 校验器 examples 5/5 + pilot 6/6 OK。仍不生成 glue HDL，也不做永久集成器。

2. 目标与范围

  • YAML 重描 PicoSoC 顶层并 validate。
  • 迭代关闭实测报告原 §9 三个缺口。
  • 不重建 RTL；不产品化集成器。

7. 迭代（0.1.3 → 0.1.5）

迭代 1 — 0.1.3-draft：fabric decode/mux

  • Schema：SoC fabric[]（kind: decode_mux、master、slaves[].match、ready_merge/rdata_merge）。
  • 校验：master 端点、target 实例、窗口重叠需 note。
  • Pilot：mem_decode 覆盖 sram / flash_xip / spimem_cfg / uart_div / uart_dat / iomem_user。
  • Demo：examples/soc/demo_soc.yaml 增加轻量 apb_decode。

迭代 2 — 0.1.4-draft：adapters

  • Schema：SoC adapters[]（partial_map|width_remap|bridge）+ fabric.slaves[].adapter。
  • 校验：to_port 在 target IP 上存在；from_role/宽度与 master bundle 对齐；omit_from_roles。
  • Pilot：mem_to_spimemio（32→24 addr）、mem_to_sram、mem_to_uart_reg。

迭代 3 — 0.1.5-draft：bit-slice

  • 端点：instance.port[N] / [M:N]；有效位宽参与连线检查。
  • Pilot：三条 IRQ 连线替代原先「只能写 note」。

9. 仍存缺口

  1. Fabric/adapters 不生成译码网表 — Agent 仍要写 Verilog mux。
  2. spimem_cfg 侧带尚未挂 adapter（仅 note）。
  3. 无 bitfield / VLNV / 厂商互换 / GUI（有意不做）。
  4. 不做永久集成器产品。

10. 声明

本 pilot 测试的是 MoonGlass_Integration 规则 / Schema / 校验包， 不是完整的重新集成工具，也不替代 PicoSoC 原有 Verilog 顶层。
